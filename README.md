# ReviewQ

네이버페이 주문내역에서 **내가 실제로 구매한 상품**의 리뷰를 템플릿 조합으로 자동 작성하는 크롬 확장(MV3)입니다.

## 시작하기 전에

이 도구는 **본인이 구매한 상품에 대한 본인 리뷰 작성**을 빠르게 하기 위한 것입니다.

- 구매하지 않은 상품의 리뷰, 대가를 받고 쓰는 허위 리뷰, 여러 계정을 동원한 리뷰 조작은 전자상거래법·표시광고법 위반이며 네이버 이용약관 위반(계정 정지 사유)입니다.
- 생성된 문장은 **실제 사용 경험과 맞는지 본인이 판단해야** 합니다. 별점과 템플릿 세트를 상품에 맞게 골라 주세요.
- 자동화 도구 사용 자체가 네이버 약관상 제재 대상이 될 수 있습니다. 사용 판단과 책임은 사용자에게 있습니다.

## 설치

```bash
git clone <이 저장소>
cd ReviewQ
npm install          # 테스트용. 확장 실행에는 필요 없습니다(빌드 단계 없음).
```

1. Chrome에서 `chrome://extensions` 접속
2. 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** → 이 폴더(`ReviewQ`) 선택

빌드 과정이 없습니다. 파일을 고치고 확장 카드의 새로고침 버튼만 누르면 반영됩니다.

## 사용 순서

첫 실행은 반드시 드라이런으로 시작하세요. 네이버 DOM은 수시로 바뀌므로 셀렉터가 맞는지 먼저 확인해야 합니다.

### 1단계 — 드라이런으로 확인

1. 네이버 로그인 후 리뷰 작성 목록 페이지를 엽니다.
2. 확장 팝업 → **설정**에서 `드라이런` 체크 확인(기본값 켜짐), `1회 최대 처리 건수`를 `1`로 설정
3. 팝업 → **실행**
4. 폼이 열려서 **별점이 눌리고 본문이 채워지는지** 눈으로 확인합니다. 등록은 되지 않습니다.

폼이 안 채워지면 [셀렉터가 안 맞을 때](#셀렉터가-안-맞을-때)로 이동하세요.

### 2단계 — 실전

1. 설정에서 `드라이런` 해제
2. `1회 최대 처리 건수`를 원하는 값으로 (처음에는 2~3건 권장)
3. 팝업 → **실행**

진행 상황과 실패 사유는 팝업에서 실시간으로 확인할 수 있고, **중단**을 누르면 현재 항목을 마치고 멈춥니다.

## 설정 항목

| 항목 | 기본값 | 설명 |
| --- | --- | --- |
| 드라이런 | 켜짐 | 폼만 채우고 등록 버튼을 누르지 않음 |
| 리뷰 목록 URL | `https://shopping.naver.com/my/writable-reviews` | 계정에서 실제로 쓰는 주소로 바꿀 수 있음 (https + naver.com 만 허용) |
| 1회 최대 처리 건수 | 10 | 사고 범위 제한. 이 수에 도달하면 자동 종료 |
| 연속 실패 시 중단 | 3 | 페이지 구조가 바뀌었을 때 무한 반복을 막음 |
| 별점 | 5 | 1~5. 별점에 따라 문장 톤이 바뀜 (4~5 긍정 / 3 중립 / 1~2 부정) |
| 최소 글자 수 | 20 | 부족하면 filler 문장을 덧붙여 채움 |
| 템플릿 세트 | 기본 | 기본 / 의류 / 식품 / 전자 / 생활용품 |
| 한 글자씩 입력 | 켜짐 | 글자 수 카운터가 `keyup`에 반응하는 폼에서 안전 |
| 상품 평가 설문 자동 선택 | 켜짐 | 맛·포장·유통기한 등 설문을 별점에 맞춰 선택. 필수인 경우 끄면 등록 불가 |
| 글자 간격 | 25~70ms | 입력 속도 |
| 건 사이 대기 | 4~9초 | 항목 사이 간격 |

설정 화면의 **샘플 3건 생성해 보기**로 실제 등록될 문장을 미리 볼 수 있습니다.

## 리뷰 본문 생성 방식

문장 조각을 슬롯 단위로 조합합니다. 예를 들어 기본 세트의 긍정 톤은 `{delivery} {quality} {closing}` 패턴에 각각 8/10/8개의 문장 후보가 있어 조합 수가 수천 가지입니다.

추가로:

- **중복 회피** — 문자 바이그램 자카드 유사도로 최근 60건과 비교해 임계값(0.72)을 넘으면 다시 조합합니다. 최대 12회 재시도 후에도 넘으면 경고를 남깁니다.
- **최소 글자 수 보장** — 부족하면 중복되지 않는 filler 문장을 덧붙입니다.
- **상품명 치환** — 템플릿 문장에 `{productName}`, `{optionName}`, `{storeName}`을 쓸 수 있습니다.

문장을 추가·수정하려면 `src/generator/templates/` 안의 파일을 고치세요. 잘못된 슬롯 참조는 `validateTemplateSet`이 잡습니다.

## 셀렉터가 안 맞을 때

네이버는 CSS 클래스명이 난독화되어 배포마다 바뀝니다. 그래서 이 확장은 클래스명 대신 **버튼 텍스트 → role/aria 속성 → 태그 구조** 순서로 요소를 찾습니다. 그래도 안 맞으면:

1. 문제가 생긴 페이지에서 팝업 → **페이지 진단**
2. 출력된 JSON의 `resolved` 항목을 봅니다. 확장이 **무엇을 폼으로 보고, 어디에 입력하고, 어떤 버튼을 누르려 하는지** 그대로 나옵니다.
3. `null`인 항목이 있으면 `bySelector`에서 실제 요소의 `tag` / `attributes` / `path`를 확인합니다.
4. **`src/content/dom/selectors.js` 한 파일만** 고칩니다. 다른 파일은 손댈 필요가 없습니다.

진단 출력에는 입력 필드의 **내용이 담기지 않습니다**(길이만 기록). 안심하고 복사해서 공유할 수 있습니다.

자세한 항목별 설명은 [docs/SELECTORS.md](docs/SELECTORS.md)를 보세요.

### 설계상 중요한 점

- **콘텐츠 스크립트는 상태를 갖지 않습니다.** 리뷰 폼이 별도 페이지로 열려 스크립트가 파괴되어도, background가 단계별로 다시 지시하고 필요하면 스크립트를 재주입합니다.
- **별점을 먼저 설정합니다.** 별점 설정이 실패하면 본문 입력과 등록을 하지 않습니다. 리뷰 폼이 아닌 페이지를 폼으로 잘못 인식했을 때 엉뚱한 곳에 입력·등록하는 것을 막는 안전장치입니다.
- **동의 체크박스를 자동으로 체크하지 않습니다.** 미체크 항목이 있으면 경고로 알립니다. 무엇에 동의하는지 모르는 채로 동의하지 않기 위함입니다.
- **`chrome.storage.session`에 매 항목마다 진행 상황을 저장합니다.** 서비스 워커가 종료되어도 상태를 잃지 않습니다.
- **중단 신호는 실행 상태와 별도 키에 둡니다.** 같은 키에 두면 실행 루프가 항목을 마치고 상태를 저장할 때 사용자가 방금 누른 중단을 덮어써 버립니다.
- **등록 성공은 "없다가 새로 나타난" 문구로만 판정합니다.** 리뷰 폼에 상시 표시되는 안내나 방금 입력한 본문이 성공으로 오탐되는 것을 막습니다.
- **폼 입력 대기 시간은 본문 길이와 타이핑 속도에서 계산합니다.** 고정값을 쓰면 느린 설정에서 입력 도중 끊깁니다.
- **리뷰 폼은 별도 팝업 창입니다.** 목록의 "리뷰쓰기" 는 같은 탭을 이동시키지 않고 `window.open` 으로 새 창을 엽니다. 그래서 목록 탭과 폼 창을 나눠 다루고, 처리 후 폼 창을 닫습니다.
- **등록 성공은 폼 창의 URL 리다이렉트로 확인합니다.** 폼 URL 의 `returnUrl` 에 `action=REVIEW_REGISTERED` 가 들어 있어, 페이지 텍스트를 뒤지는 것보다 확실합니다. 리다이렉트 직후 창이 닫힐 수 있으므로 폴링이 아니라 `tabs.onUpdated` 로 받습니다.
- **별점은 위치가 아니라 점수 텍스트로 고릅니다.** 네이버는 별점을 5,4,3,2,1 **내림차순**으로 렌더하므로 위치로 고르면 5점 요청에 1점이 눌립니다.

빌드 도구가 없으므로 import 경로 오타는 런타임에서만 드러납니다. `npm run lint:manifest`가 이를 정적으로 잡아 주니 파일을 옮긴 뒤에는 꼭 실행하세요.

커버리지 대상은 순수 로직과 DOM 로직입니다. `chrome.*` API를 직접 호출하는 접착 코드(`service-worker` / `messaging` / `keep-alive` / `content.js` / `loader` / UI)는 실제 브라우저에서만 검증할 수 있어 제외했습니다.

## 알려진 한계

1. **목록과 폼 구조는 실측으로 검증했지만, 전체 흐름을 끝까지 돌려 보지는 않았습니다.**
   - 검증됨(2026-08-27, 로그인 상태): 작성 버튼 20/20 인식, 상품명·스토어명 20/20 추출, 네비게이션 오탐 0, 별점 5→"5"·1→"1" 정확 선택, 평가 설문 그룹과 분리, 본문 `textarea#reviewInput` 인식, 등록 버튼 인식
   - 미검증: 실제 등록까지 이어지는 전체 자동 흐름(폼 창 전환 → 입력 → 등록 → 완료 확인)
   - 첫 실행은 반드시 드라이런으로, `1회 최대 처리 건수`를 1로 두고 확인하세요
2. **사진 첨부 리뷰를 지원하지 않습니다.** 포인트가 더 붙는 포토 리뷰는 수동으로 작성해야 합니다.
3. **한달사용기**는 목록에서 인식하고 결과에 `isMonthlyReview` 로 구분해 표시하지만, 폼 구조가 일반 리뷰와 달라 실패할 수 있습니다. 실측 계정에서는 20건 중 10건이 한달사용기였습니다.
8. **상품 평가 설문을 자동으로 답합니다.** 실측 폼에는 별점·본문 외에 3개 설문(맛/포장/유통기한)이 있었고 등록 버튼이 초기에 `disabled` 였습니다. 필수일 수 있어 기본값을 켜짐으로 두었고, 별점에 맞춰 선택합니다(5점 → 가장 긍정, 3점 → 중간, 1점 → 가장 부정).

   **다만 설문 중에는 사실을 묻는 항목이 섞여 있습니다.** "유통기한이 얼마나 남았나"(임박상품이에요 / 꽤남았어요 / 아주넉넉해요) 같은 항목은 별점으로 알 수 없는 값인데도 함께 답하게 됩니다. 이 점이 불편하면 설정에서 끄되, 설문이 필수라면 등록이 되지 않습니다.
4. **캡차·추가 인증이 뜨면** 해당 항목이 실패로 기록되고, 연속 실패 임계값에 도달하면 실행이 중단됩니다.
5. **완전 자동 모드는 내용 검토 없이 등록합니다.** 잘못된 템플릿이 그대로 여러 건 등록될 수 있으므로 `1회 최대 처리 건수`를 낮게 유지하세요.
6. **브라우저를 강제 종료하면** `chrome.storage.session` 상태가 사라집니다. 이미 등록된 리뷰는 그대로 남습니다.
7. **같은 상품을 여러 번 구매한 항목은 DOM 상 구별할 수 없습니다.** 네이버 목록에 항목 고유 ID가 없어서입니다. 등록 성공 시 항목이 목록에서 사라지는 것을 이용해 처리하며, 서버 반영이 지연되면 같은 건을 한 번 더 시도할 수 있습니다. 네이버가 중복 리뷰를 거부하므로 그 시도는 실패로 기록되고 이후 건너뜁니다.
